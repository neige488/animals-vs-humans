## 통합 방식

Run의 통합 브랜치는 `autopilot/core-playtest`, 통합 방식은 `batch`로 제안한다. Slice는 각자 격리 worktree에서 구현하며 테스트·독립 리뷰·제품 검증을 통과한 커밋만 통합한다. 최종 PR은 main을 대상으로 만들고 병합은 사용자 승인 후 진행한다.

## 범위와 검증 경계

- S1: 실제 Unity 프로젝트, 보유 에셋 임포트 경로, 기본 맵·카메라·이동·슬롯·라운드·HUD. 공격과 고급 봇 행동은 제외한다. 양 OS 실제 빌드·지형 접근 영상이 필요하다.
- S2: 투사체·밀치기·근접·유예·탄창과 변신 표현. 새로운 무기·특수능력은 제외한다. 공개 세션 테스트와 실제 Unity 물리·두 클라이언트 공방을 검증한다.
- S3: 같은 입력 경로를 사용하는 봇 방어·도주·추격·경로 재선택. 난이도 상품화·학습 AI는 제외한다. 실제 사람의 양 진영 경험과 세 재미 질문은 사람이 참여한 테스트로만 판정한다.
- S4: 현재·편집·예약·마지막 정상 저장본 분리, 권한·입력 검증·오류 복구 UI. 클라우드 설정 동기화는 제외한다. 격리 저장소로 실패를 재현하고 양 OS 재실행으로 확인한다.
- S5: 호스트 권한, 코드 연결, 내부 식별, 로딩 완료 인계와 봇 대체. 공개 매칭·Steam 연동·호스트 이전은 제외한다. 실제 Windows/macOS 연결과 12개 대표 클라이언트의 경합을 검증한다.

실제 서비스 선택은 기존 계정과 승인된 환경을 먼저 확인한다. 신규 비용이나 승인되지 않은 외부 인프라 변경이 필요하면 해당 부분만 blocker로 남긴다. 원본 에셋은 공개 저장소에 올리지 않는다. 임시 도형·자동 클라이언트가 실제 에셋이나 사람의 재미 평가를 대신하지 않는다.

## 게시 전 확인

모든 PA-1~PA-16에 담당 Slice가 있다. 별도 consumer 없는 foundation은 없으며 구현 의존성의 최장 경로는 S1→S2→S3이다. 사용자 확인 항목은 분할 크기, 의존 관계, 합치기·나누기, 실제 사람 검증의 HITL 분류, tdd 기본 스타일이다.

원격 main 초기화와 wrapper를 통한 누락 라벨 생성을 완료했다. 게임 코드와 유료 에셋은 초기 커밋에 포함하지 않았다.
