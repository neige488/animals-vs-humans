# Animals vs Humans — 첫 멀티플레이 재미 검증 PRD

## Problem Statement

인간이 협력해 동물을 밀어내며 버티고, 잡히면 동물로 변해 같은 라운드의 추격에 참여하는 구상을 실제 플레이로 검증할 수 있는 게임이 아직 없다. 좁은 쉘터에서의 방어, 버블건으로 밀려 떨어지는 상황, 변신 후의 추격이 양쪽 모두에게 재미있는지 문서만으로 판단하기 어렵다. 실제 참가자가 적어도 봇으로 공방을 유지하고, 라운드마다 규칙을 바꾸며 비교할 수 있는 첫 버전이 필요하다.

## Solution

보유한 Polyperfect Animal·People 에셋으로 인간·동물 캐릭터를, Synty Studios 에셋으로 작은 마을과 세 쉘터를 구성한 Unity 3인칭 게임을 만든다. 혼자 방을 열면 봇을 포함한 12명으로 시작하고, 다른 테스터는 방 코드로 참가해 인간 봇부터 이어받는다. 인간은 피해 없이 동물을 밀어내는 버블건으로 버티며 동물의 근접 공격 한 번에 변신하고, 라운드 종료 후 같은 방에서 반복한다. 호스트는 주요 규칙과 수치를 조정해 다음 라운드에 적용하고 설정을 보존한다.

첫 검증의 질문은 인간의 협력 방어·도주가 재미있는지, 동물의 접근·추격이 재미있는지, 떨어지거나 변신한 뒤에도 계속 플레이하고 싶은지다. 특수능력·상성·뽑기까지 재미가 입증됐다고 확대 해석하지 않는다.

## User Stories

1. 테스터로서, 보유 에셋으로 구성된 인간·동물·마을을 플레이하고 싶다, 실제 제작 방향의 분위기와 가독성을 검증하기 위해.
2. 혼자 접속한 테스터로서, 봇과 바로 시작하고 싶다, 다른 사람을 기다리지 않고 공방을 확인하기 위해.
3. 호스트로서, 닉네임을 입력하고 비공개 방 코드를 받고 싶다, 초대한 테스터와 같은 매치에 모이기 위해.
4. 참가자로서, 게임 회원가입 없이 닉네임과 방 코드로 참가하고 싶다, 테스트 준비 부담을 줄이기 위해.
5. Windows 또는 macOS 테스터로서, 서로 다른 OS의 참가자와 함께 플레이하고 싶다, 같은 게임 규칙과 동기화를 확인하기 위해.
6. 플레이어로서, 내 캐릭터가 보이는 3인칭 카메라와 일관된 키 배치를 원한다, 변신해도 즉시 플레이를 이어가기 위해.
7. 인간으로서, 준비 시간 동안 원하는 쉘터로 이동하고 싶다, 동료와 방어 위치를 선택하기 위해.
8. 인간으로서, 눈에 보이는 버블을 쏴 동물을 밀어내고 싶다, 명중과 낙하의 원인을 이해하고 공방을 즐기기 위해.
9. 인간으로서, 탄창을 재장전하며 동료와 번갈아 방어하고 싶다, 협력할 이유와 동물이 접근할 틈이 생기도록.
10. 인간으로서, 방어가 뚫리면 골목이나 다른 쉘터로 도망가고 싶다, 한 위치의 실패 뒤에도 플레이를 이어가기 위해.
11. 동물로서, 인간보다 조금 빠르게 달리고 버블을 피해 근접 공격하고 싶다, 접근과 타격 타이밍의 재미를 느끼기 위해.
12. 변신한 플레이어로서, 탈락하지 않고 같은 라운드에서 동물을 조작하고 싶다, 역할이 바뀌어도 참여를 지속하기 위해.
13. 플레이어로서, 점프하고 높은 곳에서 떨어져도 낙하 피해 없이 이동하고 싶다, 입체적인 도주와 추격을 만들기 위해.
14. 플레이어로서, 맵 밖에 떨어지면 상태를 유지해 지상으로 돌아오고 싶다, 테스트가 진행 불능이 되지 않도록.
15. 참가자로서, 탄생한 동물의 종류·등급과 양 진영 인원·시간을 보고 싶다, 변신과 라운드 상황을 이해하기 위해.
16. 난입자로서, 인간 봇을 우선 이어받고 없으면 동물 봇을 이어받고 싶다, 현재 공방에 바로 참여하기 위해.
17. 기존 참가자로서, 신규 참가자가 로딩하는 동안에도 봇이 계속 플레이하기를 원한다, 캐릭터가 접속 과정에서 멈추지 않도록.
18. 참가자로서, 다른 사람이 이탈하면 봇이 현재 상태를 이어받기를 원한다, 12명 공방이 유지되도록.
19. 재접속자로서, 내 자리가 봇이면 그 현재 상태를 다시 이어받고 싶다, 접속 중단 전후의 역할과 진행을 보존하기 위해.
20. 참가자로서, 가득 찬 방·연결 실패·호스트 종료를 구분해 안내받고 싶다, 다음 행동을 선택하기 위해.
21. 접속 중인 테스터로서, 연결을 취소할 수 있기를 원한다, 잘못된 방 참가나 오래 걸리는 연결을 중단하기 위해.
22. 호스트로서, 설정을 편집하고 다음 라운드에만 적용하고 싶다, 진행 중인 공방을 갑자기 바꾸지 않고 조건을 비교하기 위해.
23. 호스트로서, 아군 몸 충돌·진영 간 몸 충돌·버블건 아군 밀치기를 독립적으로 조정하고 싶다, 혼잡함과 낙하의 재미를 비교하기 위해.
24. 호스트로서, 초기·중간 변신 공격 유예를 각각 0초까지 조정하고 싶다, 유예 없는 연쇄 변신도 검증하기 위해.
25. 호스트로서, 설정을 재실행 후에도 유지하고 기본값으로 되돌릴 수 있기를 원한다, 같은 조건으로 재시험하기 위해.
26. 호스트로서, 설정 검증·저장·불러오기 실패가 기존 상태를 망가뜨리지 않기를 원한다, 테스트를 계속할 수 있도록.
27. 참가자로서, 결과와 다음 라운드 카운트다운을 보고 같은 방에서 자동으로 다시 시작하고 싶다, 여러 조건을 반복 검증하기 위해.
28. 제작자로서, 방 탐색·참가 대상 선정과 매치 내부 동작을 분리하고 싶다, 이후 공개 매칭을 추가할 때 핵심 플레이를 재사용하기 위해.

## Implementation Decisions

### 상태와 설계 확인

제품 규칙은 Grill 합의다. 아래 5개 주요 모듈 구성은 PRD 작성 중 별도 제안하고 사용자 확인을 받았다. 기존 게임 코드·공개 인터페이스·테스트 관례는 없으므로 신규 Unity 프로젝트의 설계 후보로 정의한다. 특정 패키지나 연결 서비스의 채택을 승인받은 것으로 해석하지 않는다.

### 주요 모듈 — 설계 축

| 모듈 | 작은 공개 인터페이스 후보 | 내부에 숨기는 구현 | 경계와 이유 |
|---|---|---|---|
| PlaytestSession | 방 만들기, 참가·취소·종료, 참가자 명령 전달, 세션 상태·이벤트 구독 | 방 코드, 연결 상태, 식별 검증, 슬롯 인계, 재접속, 중복 요청, 호스트와 클라이언트 연결 | 참가 과정의 복잡성을 감추고 공개 매칭·Steam 초대의 후속 연결점을 둔다. |
| MatchWorld | 라운드 시작, 참가자 입력 제출, 시간 진행, 매치 상태·사건 조회 | 이동·물리·버블·근접 타격·변신·승패·복귀·라운드 초기화 | 최종 게임 판정을 하나의 권한 경계 안에 두며 세션 발견 방식과 분리한다. |
| BotDirector | 조작할 슬롯 지정·해제, 월드 관찰 전달, 플레이 입력 생성 | 쉘터 선택, 위험 판단, 방어·도주·추격, 경로 탐색·우회 | 봇을 별도 규칙의 참가자로 만들지 않고 인간과 같은 입력·판정 경로에 연결한다. |
| PlaytestSettings | 편집·검증, 다음 라운드 적용 예약, 기본값 복원, 저장·불러오기 결과 조회 | 현재·편집·예약 설정 분리, 버전, 로컬 저장 복구, 검증 오류 | 저장 성공과 이번 실행의 적용 성공을 구분하고 취소·실패에서 상태를 보존한다. |
| GamePresentation | 로컬 입력 연결, 공개 상태·사건 표시, 캐릭터·맵 표현 구성 | 3인칭 카메라, HUD·메뉴, 에셋·애니메이션·효과음, 탄생 알림 묶기 | 표현과 판정을 분리해 모델·카메라·연출 변경이 승패나 접속 규칙을 바꾸지 않게 한다. |

인터페이스 후보는 확정된 코드 API가 아니다. 작은 인터페이스 뒤에 서로 연관된 상태와 실패 처리를 모으고, 기능 없이 호출만 전달하는 얕은 계층을 추가하지 않는다. UI가 직접 라운드 진영·슬롯·승패를 변경하거나 봇이 명중 결과를 우회해서 만들지 않는다.

### Unity와 보유 에셋

- 설치된 Unity 6000.6.3f1 arm64를 개발 출발점으로 한다. 첫 제품은 Windows·macOS 독립 실행 빌드이며 양 OS가 같은 방에서 플레이해야 한다.
- Polyperfect Animal·People에서 기본 동물·인간 각 1종을 선택하고 Synty Studios로 마을·쉘터를 구성한다. 실제 보유 팩·모델·애니메이션·렌더링 호환성을 임포트 시 검증한다.
- 에셋은 게임 표현의 자산이다. 이동, 입력, 공격 판정, 변신, 봇과 네트워크 동작은 게임 로직으로 구현한다.
- 초기 블록아웃·자동 테스트에 임시 도형을 사용할 수 있으나 보유 에셋이 실제 적용된 빌드 없이 제품 완료로 처리하지 않는다.
- 구체 모델, 맵 치수, 카메라 거리와 밸런스 초안은 사용자 위임에 따라 제작 중 정하고 선택 이유·테스트 결과를 남긴다. 소유하지 않은 에셋 구매나 원본 자산의 공개 배포는 범위에 포함하지 않는다.

### 매치와 이동

- 슬롯은 실제 참가자와 봇을 합쳐 12개다. 실제 참가자 2~4명은 초기 재미 테스트 인원이며 실제 플레이어 최대 인원을 4명으로 제한하지 않는다.
- 전원 인간으로 중앙 광장 주변에 겹치지 않게 배치한다. 준비 기본값은 20초이며 각자 쉘터로 이동한다.
- 준비 종료 시 무작위 2명은 현재 위치에서 동물이 된다. 기본 10명 인간·2명 동물로 추격전을 시작한다. 초기 동물 수는 설정 가능하다.
- 추격전 기본값은 3분이다. 종료 시 인간이 남으면 인간 팀 승리, 종료 전에 전원 변신하면 동물 팀 승리다.
- 호스트의 게임 시간으로 판정하며 종료 시각 전에 확정된 변신만 인정한다. 마지막 변신과 종료 시각이 정확히 같으면 인간 팀 승리다. 결과는 한 번 확정하고 뒤늦은 사건으로 뒤집지 않는다.
- 인간·동물 모두 3인칭, WASD 이동, 마우스 회전·조준, Space 점프, 좌클릭 공격이다. 인간의 재장전은 R이다.
- 기본 동물은 인간보다 조금 빠르다. 몸 접촉만으로 변신하지 않으며 동물의 근접 타격 한 번이 명중하면 인간이 즉시 동물이 되어 같은 라운드에 계속 참여한다.
- 최초·중간 변신의 공격 유예는 독립 설정이며 0초는 유예 없음이다. 최초 유예의 출발값은 2초이며 유예 중 이동은 가능하다. 중간 유예와 공격 수치는 제작 단계 초기값으로 정한다.
- 낙하 피해는 양 진영 모두 없다. 맵 밖 낙하는 진영·상태를 유지하고 가까운 지상 복귀 지점으로 복구한다. 쉘터 내부로 유리하게 이동하는 복귀 지점을 만들지 않는다. 정상적인 옥상 낙하는 복귀 처리하지 않는다.
- 결과를 잠깐 표시한 뒤 같은 방에서 다음 라운드를 자동 시작한다. 전원 인간·시작 위치·라운드별 상태를 초기화하고 새 최초 동물을 선정한다.

### 쉘터와 봇

- 맵은 작은 마을 한 개이며 옥상·구석·창고 쉘터 3곳을 초안으로 한다. 광장을 통과하는 빠르고 노출된 길과 시야가 끊기는 골목 우회로를 연결한다.
- 쉘터는 공간이 비좁다는 의미이며 시스템의 입장 인원 제한이나 무적 안전지대가 아니다. 첫 버전에서는 특수능력 없이 모든 쉘터에 접근할 길을 둔다.
- 인간 봇은 쉘터에 모여 버블건으로 방어하고 위험해지면 다른 쉘터로 도주한다. 동물 봇은 추격·근접 공격하며 길이 막히면 다른 접근 경로를 찾는다.
- 봇의 위험 기준·목표 선택·명중률·반응 속도는 테스트로 조정한다. 경로만 이동하거나 제자리에서 공격하는 수준으로 공방 검증을 대체하지 않는다.

### 버블건과 충돌

- 버블은 눈에 보이는 투사체다. 명중하면 터지며 대상을 밀어내고 피해·처치는 발생시키지 않는다.
- 벽·바닥 명중 시 터진다. 빗나간 버블은 사거리 또는 유지 시간을 넘으면 사라진다. 물체가 무한히 누적되지 않도록 수명과 자원 반환을 관리한다.
- 예비 탄약은 무제한이지만 탄창을 소모하면 재장전이 필요하다. 탄창·재장전·버블 크기·비행 속도·사거리·유지 시간·연사·밀치는 힘은 설정으로 조정한다.
- 아군 몸 충돌, 인간·동물 간 몸 충돌, 버블건 아군 밀치기는 서로 독립된 설정이며 첫 테스트에서는 모두 켠다.
- 아군 몸 충돌을 끄면 같은 진영끼리 통과한다. 진영 간 몸 충돌을 끄면 서로 통과하되 근접 공격의 명중 판정은 별개로 유지한다.
- 버블건 아군 밀치기를 끄면 버블이 아군을 통과한다. 켜면 아군도 밀릴 수 있다. 신체 충돌 설정이 버블 피격 옵션을 대신하지 않는다.

### 방·난입·이탈

- 첫 테스트는 참가자 한 명이 플레이와 게임 서버를 함께 실행하는 비공개 플레이어 호스트 방식이다. 방 코드로 참가하며 별도 게임 회원가입은 없다.
- 닉네임은 표시용이다. 재접속과 중복 참가 판별에는 별도 내부 식별자를 사용하고 참가자가 닉네임만으로 다른 사람의 슬롯을 가져갈 수 없게 검증한다.
- 방 만들기는 유효한 닉네임, 참가는 유효한 닉네임과 코드가 필요하다. 입력 오류는 항목별로 표시하고 관련 버튼을 비활성화한다.
- 난입은 인간 봇을 우선 배정하고 인간 봇이 없을 때 동물 봇을 배정한다. 진영별 인원과 총원을 새로 늘리지 않는다.
- 로딩·연결 준비 중에는 봇이 계속 플레이한다. 준비 완료 시점의 최신 진영·위치·무기·유예 등 상태를 이어받고 조작권을 한 번 인계한다. 준비 중 변신이 일어나면 인계 시점의 동물 상태를 받는다.
- 종료 직전까지 봇이 있으면 난입할 수 있다. 결과 표시 중 참가자는 다음 준비 구간부터 플레이한다.
- 일반 참가자가 이탈하면 같은 상태를 봇이 이어받는다. 마지막 인간의 이탈만으로 동물 승리를 만들지 않는다.
- 같은 라운드에 재접속하면 원래 슬롯이 봇인 경우 그 현재 상태를 우선 이어받는다. 동물이 되었다면 동물로 복귀한다. 원래 자리에 사람이 있으면 기존 사람을 유지하고 일반 난입 우선순위를 따른다.
- 12명 모두 실제 참가자이면 정원 초과를 안내하고 재시도·돌아가기를 제공한다. 마지막 자리는 호스트가 먼저 합류를 확정한 한 명만 차지한다. 중복 요청·재시도로 같은 참가자가 두 자리를 차지하지 않는다.
- 연결 실패 시 재시도·돌아가기를 제공한다. 연결 중 취소하면 시작 화면으로 돌아가며 늦은 성공 응답으로 입장하지 않는다. 실패·취소 동안 기존 봇과 매치는 유지한다.
- 호스트 종료·호스트 연결 상실은 승패 없는 라운드 중단이다. 이유와 시작 화면으로 돌아가는 동작을 제공한다. 첫 버전은 호스트 이전·별도 전용 서버 운영을 하지 않는다.
- 방 탐색·참가 대상 선정과 매치 내부 동작을 분리한다. 방 코드 구현에는 별도의 연결 기반이 필요하며 Steam 출시 자체가 이를 자동 제공하는 것으로 가정하지 않는다.

### 설정과 표현

- 설정 상태는 현재 라운드, 편집 중, 다음 라운드 적용 예약, 마지막 정상 저장본을 구분한다. 호스트만 매치 설정을 바꾼다.
- Esc 메뉴의 라운드·이동·버블건 범주에서 편집한다. 메뉴가 열려도 매치는 계속된다. 적용은 다음 라운드를 예약하며 모든 참가자·봇에 같은 설정을 적용한다.
- 취소는 편집 내용을 버리고 기존 예약을 유지한다. 기본값 복원도 편집값만 바꾸며 별도 적용 전에는 현재·예약·저장 상태를 바꾸지 않는다.
- 잘못된 값은 항목별 이유를 표시하고 적용을 막는다. 라운드 시간은 양수이며 유예 0초는 유효하다. 다른 범위는 구현 시 정의하고 허용 범위와 기본값을 문서화한다.
- 정상 저장 설정은 재실행 후 복원한다. 최초 실행은 기본값으로 시작한다. 손상된 저장본은 보존하고 안내 후 기본값으로 진행한다.
- 저장 실패가 이번 실행의 예약 적용을 막지는 않는다. 마지막 정상 저장본을 보존하고 변경값의 재실행 미유지·재시도·닫기를 안내한다.
- HUD에는 양 진영 인원, 시간, 내 진영, 조준점, 인간 탄창·재장전 또는 동물 근접 공격 상태를 표시한다. 캐릭터를 화면에서 보이게 유지한다.
- 최초·중간 동물 탄생을 종류·등급 글자 배지와 색상으로 상단에 알리고 플레이를 멈추지 않는다. 거의 동시 탄생은 종류·등급별 수량으로 묶는다.
- 사용자에게 보이는 변신 용어와 Grill에서 승인한 화면 문구·배치를 따른다. 예시 동물·희귀도·탄창 숫자를 실제 모델 배정이나 밸런스 합의로 오인하지 않는다.

## Testing Decisions

### 공개 경계 — 테스트 축

이 테스트 경계는 주요 모듈 설계와 별도로 제안하고 사용자 확인을 받았다. 핵심 자동 검증은 PlaytestSession의 공개 게임 실행 경계 한 곳에 모은다. 방 만들기·참가·취소, 참가자 플레이 입력, 설정 편집·적용을 호출하고 공개 스냅샷·이벤트·UI 결과를 관찰한다. MatchWorld·BotDirector·저장 구현의 private 함수나 내부 컬렉션에 직접 결합한 테스트를 만들지 않는다.

현재 재사용할 기존 테스트 경계는 없다. 신규 경계는 실제 제품의 진입점과 같은 경로를 호출해야 하며 테스트 전용 가짜 게임으로 대체하지 않는다. 테스트 드라이버는 이 공개 경계를 구동하고 증거를 모으는 수단이며 새로운 제품 기능이 아니다.

### 검증 위치와 대체 허용 범위

- Unity Edit Mode의 공개 세션 통합 검증: 권한, 라운드 상태·종료 경계, 슬롯 우선순위·중복·재시도, 현재·예약 설정을 검사한다. 시계·난수·연결·저장 실패는 외부 의존성 경계에서 제어한다.
- Unity Play Mode: 동일 진입점으로 실제 씬·충돌·투사체·3인칭·내비게이션을 실행한다. 거리 계산이나 상태 변화만으로 물리적 밀치기·지형 접근·카메라 결과를 대체하지 않는다.
- 독립 실행 빌드: 실제 Windows·macOS 참가자와 실제 방 코드 연결을 사용해 난입·재접속·전투를 검증한다. 로컬 다중 프로세스는 경합·정원 검증에 사용하되 사람의 재미 평가를 대신하지 않는다.
- 대표 실패 주입은 representative로 표시한다. 저장 실패를 만들려고 사용자 원본을 손상시키거나 실제 디스크를 채우지 않는다. 격리된 저장소·전송 어댑터로 오류를 재현하고 같은 사용자 흐름에서 결과를 관찰한다.
- 에셋 임포트·최종 렌더링·실제 네트워크·플레이 감상은 live 근거가 필요하다. mock 성공을 live 성공으로 보고하지 않는다.
- 재현 자료에는 빌드 식별자, OS, 설정 스냅샷, 참가자/봇 수, 라운드·사건 시각을 남긴다. 내부 식별자 비밀값·접속 토큰은 제외한다.

## Product Definition of Done

- **Target environment:** Unity 개발 환경과 Windows·macOS 독립 실행 빌드. 비공개 방에서 실제 테스터 2~4명과 나머지 봇으로 12명을 채운다. 혼자 시작하는 경우도 검증한다. 실행한 OS·기기·Unity 버전을 증거에 남긴다.
- **Core value delivered:** 보유 에셋으로 구성된 마을에서 방어·도주·추격·밀치기·변신·자동 라운드 반복을 실제로 플레이할 수 있다. 접속만 성공하거나 빈 씬이 뜨는 상태는 완료가 아니다.
- **Persistence/read-back:** 호스트의 적용 설정은 재실행 후 화면과 다음 매치에서 읽어 확인한다. 현재 라운드와 예약 버전은 참가자 사이에 일치해야 한다. 보상·계정 진행의 영구 저장은 첫 범위가 아니다.
- **Failure/degraded behavior:** 설정 오류·저장 실패·손상, 연결 실패·취소, 동시 참가·정원 초과, 이탈·재접속, 호스트 종료를 아래 PA 시나리오대로 관찰한다.
- **Evidence:** 모든 critical PA에 결과, 사용한 빌드·설정, live/representative 구분, 필요한 화면·영상·공개 사건 기록을 연결한다. 한 장의 시작 화면이나 테스트 suite green으로 플레이 검증을 대신하지 않는다.
- **Fun validation:** 실제 사람이 인간·동물 양쪽 역할을 플레이한 뒤 세 가지 재미 질문에 대한 관찰과 의견을 남긴다. 강점·막힘·다음 조정값을 결정할 수 있어야 한다. 승률이나 점수의 임의 목표를 사용자 합의로 만들지 않는다. 구현 검수 통과와 재미에 대한 긍정 판단은 구분해 보고한다.
- **Completion rule:** critical PA가 모두 재현·통과하고 실제 OS 간 플레이·보유 에셋 적용·설정 재조회·재미 검토 근거가 있어야 제품 구현 완료로 선언한다. 실패·미실행은 그대로 남기고 완료로 치환하지 않는다.
- **Allowed verification effects:** 격리된 로컬 테스트 데이터 생성·빌드·실행·설정 저장, 동의한 테스터 간 비공개 세션, 승인된 테스트 연결 환경의 한시적 방 생성·종료, 공식 문서와 기존 서비스 상태의 읽기 전용 확인.
- **Authorization blockers:** 새 유료 서비스·비용 한도 증가, 외부 계정/인프라의 승인되지 않은 변경, 공개 게임 배포·원본 에셋 공개, 원본 데이터 삭제·보안 완화는 제품 통과 조건과 분리한다. 승인된 연결 환경이 없으면 그 의존성을 명시하고 local 검증을 먼저 진행하며 live 완료를 주장하지 않는다.

## Product Acceptance Scenarios

### PA-1 — 보유 에셋으로 혼자 시작 (critical)

- **Environment:** Windows·macOS 각 독립 실행 빌드, live.
- **Initial state:** 보유 팩이 적용된 새 빌드, 테스트 설정이 없는 격리 프로필.
- **Action:** 닉네임을 입력해 방을 만들고 준비 구간부터 추격전까지 플레이한다.
- **Observable result:** 방 코드가 생성되고 본인+11봇으로 시작한다. Polyperfect 인간·동물과 Synty 마을이 보이고 옥상·구석·창고 쉘터가 있다. 전원 인간으로 겹치지 않게 출발한 뒤 기본 20초 후 현재 위치의 2명이 동물로 변한다.
- **Persistence/read-back:** 새 실행에서 적용한 기본 설정과 총 12슬롯을 조회하고 사용한 에셋 목록을 확인한다.
- **Failure/degraded:** 필수 자산 누락·렌더링 오류·방 생성 불가는 실패다. 첫 설정 파일 부재는 오류가 아니다.
- **Evidence:** 양 OS 빌드 정보, 시작부터 변신까지 영상, 모델·맵 자산 사용 내역과 설정 스냅샷.
- **Cleanup:** 테스트 방과 실행 프로세스를 종료하고 격리 프로필만 정리한다.

### PA-2 — 3인칭 이동·점프·낙하·복귀 (critical)

- **Environment:** 양 OS 빌드와 실제 맵, live.
- **Initial state:** 인간 및 동물을 각각 조작 가능한 라운드.
- **Action:** WASD·마우스·Space로 세 쉘터에 접근하고 옥상에서 낙하한다. 별도 격리 실행에서 맵 바깥 낙하도 재현한다.
- **Observable result:** 자기 캐릭터가 보이는 3인칭을 유지하고 양 진영 모두 기본 이동으로 쉘터에 접근한다. 동물은 기본 설정에서 조금 빠르다. 정상 낙하는 피해 없이 이어지고 맵 밖 낙하만 상태를 보존해 쉘터 밖 지상으로 복구된다.
- **Persistence/read-back:** 낙하 전후 진영·슬롯·무기 상태를 비교한다. 디스크 저장은 해당 없음.
- **Failure/degraded:** 지형 끼임·복귀 반복·쉘터 안으로 이득을 얻는 복귀는 결함으로 남긴다.
- **Evidence:** 조작·카메라·경로·낙하 영상과 복귀 전후 공개 상태.
- **Cleanup:** 테스트 라운드를 종료하고 재현용 시작 상태를 초기화한다.

### PA-3 — 버블건과 근접 변신 공방 (critical)

- **Environment:** 실제 두 클라이언트 빌드 및 Unity Play Mode, live.
- **Initial state:** 인간과 동물이 접근 가능한 상태, 설정과 탄창을 기록한다.
- **Action:** 인간은 이동하는 동물을 향해 발사·재장전하고 동물은 버블을 피해 접근·좌클릭 공격한다. 접촉만 하는 경우와 명중·빗나감도 비교한다.
- **Observable result:** 버블이 실제로 날아가 명중 시 터지고 대상을 밀며 피해·처치는 없다. 지형 명중과 거리·수명 만료로 소멸한다. 탄창 소모와 R 재장전이 작동하고 예비 탄약은 소진되지 않는다. 몸 접촉은 변신하지 않으며 근접 명중 한 번으로 즉시 동물이 되어 같은 입력으로 추격을 이어간다.
- **Persistence/read-back:** 양 클라이언트의 진영·인원·탄창·변신 사건이 일치한다. 라운드 종료 후 전원 인간 상태로 재설정된다.
- **Failure/degraded:** 유예가 활성화된 동안 공격은 성립하지 않고 이동은 가능하다. 유예 0초에서는 해당 제한이 없다.
- **Evidence:** 호스트·참가자 시점 영상, 명중·변신 시각 및 슬롯 상태, 수명 종료 후 버블 수 관찰.
- **Cleanup:** 테스트 라운드와 남은 투사체를 정리한다.

### PA-4 — 충돌·아군 밀치기 독립 비교 (critical)

- **Environment:** 실제 클라이언트 2명 이상과 봇, 좁은 쉘터, live.
- **Initial state:** 아군 몸 충돌·진영 간 충돌·아군 버블 밀치기 모두 켠 기본 설정.
- **Action:** 아군끼리 통로를 지나고 버블로 동료를 밀며, 각 옵션을 하나씩 꺼 다음 라운드와 비교한다.
- **Observable result:** 몸 충돌 옵션과 투사체 옵션이 독립적으로 바뀐다. 아군 버블 밀치기를 끄면 버블이 아군을 통과한다. 켜면 동료도 밀려 떨어질 수 있다. 진영 간 충돌 변경은 자동 접촉 변신을 만들지 않는다.
- **Persistence/read-back:** 각 라운드 설정 버전과 모든 클라이언트의 해당 효과가 일치한다.
- **Failure/degraded:** 옵션 하나 변경이 다른 옵션을 조용히 바꾸면 실패다.
- **Evidence:** 설정 조합표와 옵션별 같은 장소의 비교 영상.
- **Cleanup:** 설정을 기본값으로 예약 복원하고 테스트 방을 종료한다.

### PA-5 — 봇이 만드는 쉘터 공방 (critical)

- **Environment:** 혼자+11봇 및 실제 2~4명+나머지 봇 빌드, live.
- **Initial state:** 기본 맵과 실제 이동·전투 판정을 사용한다.
- **Action:** 인간 봇과 함께 방어하고 동물 접근·진입로 봉쇄 상황을 만든다. 동물로도 참가해 인간 봇의 도주를 관찰한다.
- **Observable result:** 인간 봇이 쉘터에 모여 발사·재장전하고 위험하면 다른 쉘터로 이동한다. 동물 봇은 추격·공격하고 막힌 길에서는 우회한다. 사람이 적어도 공방과 역할 전환이 발생한다.
- **Persistence/read-back:** 공개 참가자 상태와 위치·공격 사건을 영상과 대조한다. 내부 AI 상태를 통과 조건으로 삼지 않는다.
- **Failure/degraded:** 영구 정지·접근 불가·플레이 없는 전원 배회는 실패로 분류한다.
- **Evidence:** 양 진영 시점의 연속 영상과 문제 경로·사용 설정 기록.
- **Cleanup:** 임시 재현 장애물과 테스트 프로세스를 정리한다.

### PA-6 — 승패·종료 경계·자동 반복 (critical)

- **Environment:** live 빌드의 양 승리 경로, 공개 세션 경계의 representative 시계 제어.
- **Initial state:** 인간 생존·전원 변신 각각을 만들 수 있는 라운드.
- **Action:** 시간까지 생존하거나 종료 전에 마지막 인간을 변신시킨다. 자동 검증에서는 마지막 변신을 종료 직전·동일 시각·직후로 실행한다.
- **Observable result:** 생존은 인간 승리, 종료 전 전원 변신은 동물 승리다. 정확히 같은 시각은 인간 승리이며 지연 사건으로 결과가 뒤집히지 않는다. 결과 카운트다운 뒤 같은 방에서 전원 인간·광장 주변 출발·새 동물 선정이 반복된다.
- **Persistence/read-back:** 양 클라이언트 결과와 라운드 ID·설정 버전 일치, 이전 라운드 사건이 새 라운드를 바꾸지 않음을 확인한다.
- **Failure/degraded:** 호스트 상실은 이 승패 흐름 대신 PA-12의 중단으로 처리한다.
- **Evidence:** 양 결과·다음 준비 영상 및 경계 시각의 자동 검증 결과.
- **Cleanup:** 시간 제어는 격리 실행에서 해제하고 라운드를 종료한다.

### PA-7 — 실제 OS 간 방 코드 난입 (critical)

- **Environment:** Windows·macOS의 실제 별도 클라이언트, 승인된 실제 연결 기반, live. 동일 프로세스 fixture는 대체 불가.
- **Initial state:** 호스트가 봇과 시작했으며 두 OS를 포함한 2~4명의 사람이 참가할 수 있다.
- **Action:** 방 코드를 공유받아 준비·추격전 후반에 참가한다. 가능한 환경에서 호스트 OS를 바꿔 같은 흐름을 확인한다.
- **Observable result:** 회원가입 없이 참가하고 총 12명을 유지한다. 인간 봇이 있으면 인간을, 없으면 동물을 이어받는다. 입력·버블·변신·HUD가 양 OS에서 동일 매치로 동작한다. 결과 중 참가하면 다음 준비부터 플레이한다.
- **Persistence/read-back:** 호스트와 참가자의 슬롯·진영·라운드·설정 버전을 대조한다. 새 방 생성 없이 다음 라운드까지 유지한다.
- **Failure/degraded:** 유효하지 않은 입력은 진행 차단, 존재하지 않거나 연결 불가한 방은 오류 안내·재시도·돌아가기를 제공한다.
- **Evidence:** 양 OS 동시 영상, 실제 연결 방식·네트워크 조건, 공개 세션 상태와 빌드 식별자.
- **Cleanup:** 한시적 테스트 방과 연결 자원을 정상 종료한다. 공유된 방 코드는 증거에서 가린다.

### PA-8 — 합류 준비 중 봇 유지·실패·취소 (critical)

- **Environment:** 실제 세션 및 대표 지연·실패를 주입한 공개 연결 경계, live/representative 병기.
- **Initial state:** 참가 예정 슬롯을 봇이 조작 중이다.
- **Action:** 클라이언트 준비를 지연시키고 그동안 봇의 이동·변신을 진행한다. 성공, 실패, 취소 후 늦은 성공 응답을 각각 재현한다.
- **Observable result:** 준비 중 봇이 계속 움직인다. 성공 시 인계 순간의 최신 상태를 받는다. 실패·취소 시 봇이 유지되고 취소 후 늦은 성공으로 화면이나 슬롯이 참가 상태가 되지 않는다.
- **Persistence/read-back:** 인계 전후 슬롯은 하나이며 총원·현재 진영·조작 주체가 일치한다.
- **Failure/degraded:** 오류에서 재시도·돌아가기, 연결 중 취소에서 시작 화면 복귀가 작동한다.
- **Evidence:** 진행 중 영상과 조작 주체 전환·취소 결과 사건. 주입 조건을 명시한다.
- **Cleanup:** 지연·오류 주입을 제거하고 남은 참가 예약을 해제한다.

### PA-9 — 일반 이탈과 상태 승계 재접속 (critical)

- **Environment:** 실제 두 클라이언트 이상, live.
- **Initial state:** 인간 참가자의 슬롯과 내부 식별을 같은 클라이언트에서 유지한다.
- **Action:** 참가자가 이탈한 뒤 봇이 플레이하고 변신하도록 한다. 같은 라운드에 재접속한다. 다른 사람이 원래 자리를 차지한 변형도 실행한다.
- **Observable result:** 이탈 즉시 봇이 이어받아 12명을 유지한다. 원래 슬롯이 봇이면 그 현재 동물 상태를 우선 승계한다. 원래 슬롯이 사람이면 그 사람을 내보내지 않고 남은 인간 봇 우선으로 배정하며 없으면 정원 초과다.
- **Persistence/read-back:** 같은 라운드의 슬롯 이력과 현재 상태를 대조한다. 닉네임을 같게 만든 다른 참가자가 원래 사람의 슬롯을 가져가지 못한다.
- **Failure/degraded:** 마지막 인간의 일반 이탈만으로 동물 승리가 생기지 않는다. 호스트 이탈은 별도 중단이다.
- **Evidence:** 이탈 전·봇 조작 중·복귀 후 영상과 공개 슬롯 이력.
- **Cleanup:** 테스트 참가자 식별 정보는 격리 프로필과 함께 정리한다.

### PA-10 — 정원·동시 참가·중복 요청 (critical)

- **Environment:** 실제 게임 실행 경계를 사용하는 다중 클라이언트 검증. 12개의 사람이 직접 조작할 필요는 없으며 representative 자동 클라이언트 허용.
- **Initial state:** 11개 실제 클라이언트 슬롯과 1봇이 있는 격리 매치.
- **Action:** 두 클라이언트가 마지막 자리에 동시에 참가하고 동일 참가 요청을 재시도한다. 가득 찬 뒤 추가 참가한다.
- **Observable result:** 호스트가 먼저 확정한 한 명만 입장하고 총원은 12다. 다른 클라이언트는 정원 초과를 받는다. 중복 요청으로 슬롯이나 조작권이 중복되지 않는다.
- **Persistence/read-back:** 호스트와 각 클라이언트에서 12슬롯 및 유일한 소유자를 재조회한다.
- **Failure/degraded:** 정원 초과 화면에서 재시도·돌아가기가 동작하고 기존 참가자를 내보내지 않는다.
- **Evidence:** 경합 순서·요청 결과·슬롯 스냅샷과 정원 초과 UI.
- **Cleanup:** 자동 클라이언트와 테스트 방을 종료한다.

### PA-11 — HUD와 묶인 동물 탄생 알림 (critical)

- **Environment:** 실제 인간·동물 클라이언트 화면, live.
- **Initial state:** 기본 탄생과 여러 변신을 발생시킬 수 있는 매치.
- **Action:** 준비 종료·재장전·중간 변신·동시 변신을 관찰하고 진영을 전환한다.
- **Observable result:** 상단 인원·시간, 중앙 조준점, 하단 진영·무기 상태와 보이는 내 캐릭터가 유지된다. 탄생은 종류·등급 글자와 색상을 함께 표시한다. 동시 사건은 같은 종류·등급 수량으로 묶이고 플레이가 멈추지 않는다.
- **Persistence/read-back:** 화면 인원과 사건 수량을 호스트 공개 상태와 대조한다. 저장은 해당 없음.
- **Failure/degraded:** 개별 팝업 누적으로 추격 화면을 가리거나 재장전·변신 전 상태가 계속 남으면 결함이다.
- **Evidence:** 승인된 구도와 비교 가능한 각 상태 화면·연속 영상.
- **Cleanup:** 재현용 사건 조건을 초기화한다.

### PA-12 — 호스트 종료 (critical)

- **Environment:** 실제 호스트·원격 참가자 빌드, live.
- **Initial state:** 추격전 진행 중.
- **Action:** 호스트를 정상 종료하고, 별도 실행에서는 연결 상실을 재현한다.
- **Observable result:** 참가자는 연결 종료와 이번 라운드 중단 안내를 받는다. 팀 승패로 처리하지 않고 시작 화면으로 돌아갈 수 있다.
- **Persistence/read-back:** 이전 방의 조작·늦은 사건이 시작 화면 또는 새 방 상태를 바꾸지 않는다.
- **Failure/degraded:** 연결 상실 감지까지의 실제 시간을 기록한다. 영구 대기나 호스트 이전이 된 것처럼 보이는 거짓 안내는 실패다.
- **Evidence:** 종료 전후 양쪽 영상, 중단 결과와 새 방 시작 확인.
- **Cleanup:** 남은 테스트 방·프로세스를 종료한다.

### PA-13 — 설정 편집·예약·취소·복원·권한 (critical)

- **Environment:** 호스트·참가자 실제 빌드, live.
- **Initial state:** 현재 설정 A, 다음 라운드 예약 B를 구분할 수 있는 매치.
- **Action:** Esc로 값과 옵션을 편집하고 취소·기본값 복원·적용을 각각 실행한다. 일반 참가자의 변경 시도도 확인한다.
- **Observable result:** 메뉴 중 매치는 진행된다. 편집·복원만으로 A나 B가 바뀌지 않는다. 취소는 편집을 버리고 예약을 유지한다. 적용하면 다음 라운드에 모두 동일한 새 값을 받는다. 일반 참가자는 변경할 수 없다.
- **Persistence/read-back:** 현재·예약 설정 버전과 다음 라운드 양 클라이언트 효과를 읽어 비교한다.
- **Failure/degraded:** 음수 라운드 시간은 항목별 이유·버튼 비활성화로 막고 이전 상태를 유지한다. 공격 유예 0초는 정상 적용된다.
- **Evidence:** 각 편집 상태 화면, 설정 버전, 실제 이동·충돌·유예 비교 결과.
- **Cleanup:** 기본값을 정상 적용하고 테스트 방을 종료한다.

### PA-14 — 설정 저장과 재실행 (critical)

- **Environment:** 양 OS의 격리 로컬 프로필과 실제 빌드, live.
- **Initial state:** 초기 설정 또는 기존 정상 저장 설정.
- **Action:** 호스트가 구분 가능한 유효 설정을 적용하고 종료 후 다시 실행해 방을 만든다.
- **Observable result:** 저장된 값이 화면에 복원되고 새 매치에서 실제로 적용된다. 최초 실행은 기본값으로 정상 시작한다.
- **Persistence/read-back:** 저장 직후, 재실행 화면, 새 라운드 효과의 세 지점을 대조한다.
- **Failure/degraded:** 저장값과 UI만 일치하고 게임 효과가 다르면 실패다. 읽기 실패는 PA-15로 검증한다.
- **Evidence:** 저장·재실행·새 라운드 영상과 설정 스냅샷.
- **Cleanup:** 사용자 설정을 건드리지 않고 테스트 프로필만 정리한다.

### PA-15 — 저장·불러오기 실패 복구 (critical)

- **Environment:** 실제 설정 UI와 격리 저장소, representative 오류 주입.
- **Initial state:** 정상 저장 A와 편집한 B가 있다. 별도 복사본에 손상된 설정을 준비한다.
- **Action:** 저장 오류를 발생시키고 다음 라운드를 진행한 뒤 재시도한다. 손상된 설정으로 별도 실행한다.
- **Observable result:** 저장 실패는 재실행 미유지를 안내하지만 이번 실행의 B 예약은 유지한다. 정상 파일 A를 보존한다. 손상본은 보존하고 안내 후 기본값으로 플레이한다.
- **Persistence/read-back:** 실패 직후 정상 저장본의 내용, 다음 라운드 B, 재시도 성공 후 재실행 값을 읽어 확인한다. 손상본도 보존되어야 한다.
- **Failure/degraded:** 오류를 숨기거나 정상 파일을 손상시키면 실패다. 실제 사용자 저장본 삭제·디스크 고갈을 유발하지 않는다.
- **Evidence:** 오류 안내·재시도 화면, 설정 상태, 격리 파일 보존·재조회 결과.
- **Cleanup:** 오류 주입과 격리 복사본만 정리한다.

### PA-16 — 실제 참가자의 재미 검토 (critical)

- **Environment:** 실제 사람 2~4명, 나머지 봇, 보유 에셋이 적용된 빌드, live.
- **Initial state:** 기본 설정과 비교할 설정을 기록하고 모두 인간·동물 양쪽을 경험할 수 있게 라운드를 반복한다.
- **Action:** 협력 방어·도주, 동물 접근·공격, 낙하·변신 후 추격을 플레이한다. 아군 충돌·밀치기 또는 유예를 바꿔 비교한다.
- **Observable result:** 세 재미 질문 각각에 구체적인 플레이 장면과 참가자 의견을 연결한다. 계속할지, 어떤 값을 조정할지, 공방에 구조적인 문제가 있는지 판단할 자료가 남는다.
- **Persistence/read-back:** 빌드·설정별 관찰을 다시 읽고 같은 조건으로 재현할 수 있다. 임의의 만족도 숫자를 통과선으로 만들지 않는다.
- **Failure/degraded:** 접속 문제·봇 정지로 양 역할을 경험하지 못했다면 검증 미완료다. 재미가 약하다는 결과는 숨기지 않고 후속 수정 대상으로 보고한다.
- **Evidence:** 동의한 참가자의 플레이 영상 또는 장면 기록, 세 질문의 피드백, 다음 조정안. 민감한 식별 정보는 남기지 않는다.
- **Cleanup:** 테스트 방 종료, 일회성 공유 코드 폐기, 필요 없는 원시 자료 정리.

## Out of Scope

- 캐릭터별 특수능력·상성, Balloon맨, 여러 캐릭터 수집·뽑기·과금·진행 보상.
- 추가 무기·무기 선택 화면, 맵 여러 개, 확정된 출시 인원 확대.
- 공개 자동 매칭, Steam 계정·친구 초대 연동, 게임 회원가입.
- 호스트 이전, 별도 전용 서버 운영, 관전·입장 대기열.
- 모바일·게임패드 지원, macOS 정식 출시 확정, 공개 Steam 출시 작업.
- 모든 최종 밸런스의 확정, 경쟁전 수준의 부정행위 방지 인증, 출시 규모 부하 보증.
- 테스트 통과만으로 최종 특수능력 공방·수집 시스템의 재미를 입증했다고 주장하는 것.

## Further Notes

- 이 문서는 Grill에서 승인한 제품 방향·화면 흐름을 실행 계약으로 합성한다. 희귀도·동물 이름·탄창 숫자의 화면 예시는 실제 밸런스 배정이 아니다.
- 확정 기본값은 12슬롯, 최초 동물 2명, 준비 20초, 추격전 3분, 최초 공격 유예 2초, 세 충돌·아군 밀치기 옵션 켜기다. 유예와 수치는 테스트에서 바꿀 수 있다. 나머지 초기값은 제작자 선택임을 명시해 문서화한다.
- 기술 선정은 먼저 작은 실제 접속·물리 검증으로 Unity·Windows·macOS·방 코드·호스트 방식의 호환성을 확인한다. 외부 서비스 비용·권한이 필요하면 해당 부분만 별도 권한 의존성으로 드러낸다.
- 비공개 방 코드와 내부 식별자의 수명·위조 방지·재접속 검증을 정의해야 한다. 닉네임을 인증 수단으로 사용하지 않는다.
- 현재 게임 구현과 실행 검증은 아직 없다. 이 PRD의 시나리오는 향후 완료 판정 계약이며 이미 통과한 결과가 아니다.
- 주요 모듈과 테스트 경계는 각각 사용자 확인을 받았다. 후속 단계에서 세로 기능 단위로 분할하고 통합 전략을 결정한다.
