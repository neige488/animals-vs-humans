# Animals vs Humans — 실감 개선 PRD

## Problem Statement

현재 프로토타입은 컨셉의 재미는 확인됐지만 움직임과 반응이 모두 "즉시"로 처리되어 장난감처럼 느껴진다. 캐릭터는 첫 순간부터 최고 속도로 달리고 손을 떼면 바로 멈추며, 걷기·점프·착지·공격·피격 동작 없이 대기와 달리기만 재생된다. 동물의 공격은 휘두르는 동작 없이 클릭한 순간 판정되고, 버블에 맞아도 반응이 없으며, 변신은 모델이 그 자리에서 바뀌어 끼워질 뿐이다. 소리는 2D 합성음 두 개뿐이라 동물이 다가오는 것을 귀로 느낄 수 없고, 원격 참가자와 봇은 들쭉날쭉하거나 지그재그로 움직여 기계처럼 보인다. 그 결과 인간의 협력 생존 긴장감과 동물의 추격 손맛이 화면과 소리로 충분히 전달되지 않는다.

## Solution

로우폴리 Polyperfect·Synty 스타일을 유지한 채 **실감**(game feel)을 높인다. 캐릭터는 무게감 있게 출발·정지하고 속도에 맞는 걷기·달리기·점프·착지 동작을 보인다. 동물은 예비동작과 스윙으로 공격하고, 버블에 맞은 동물은 비틀거리며 밀려난다. 변신은 짧은 연출로 전달되며, 관련된 사람의 카메라만 흔들리고 짧게 멈춘다. 동물의 발소리·울음·환경음·단계별 배경음악이 3D 공간음으로 들려 다가오는 위협을 귀로 느낀다. 원격 참가자와 봇도 사람처럼 자연스럽게 움직이고, 마을은 흔들리는 나무·깃발·밀리는 소품·빛나는 랜턴으로 살아 있는 장소가 된다. 승패에 영향을 주는 연출은 기본값을 작게 두고 호스트가 실시간으로 조절하거나 끌 수 있어, 실감과 조작 반응성의 균형을 실플레이로 비교할 수 있다.

## User Stories

1. 인간 플레이어로서, 달리기 시작과 멈춤에 약간의 무게감이 있기를 원한다, 내 캐릭터가 실제 몸처럼 느껴지도록.
2. 인간 플레이어로서, 관성이 있어도 방향 전환이 둔하지 않기를 원한다, 동물에게서 도망칠 때 조작이 답답하지 않도록.
3. 플레이어로서, 이동 속도에 맞춰 걷기와 달리기 동작이 자연스럽게 섞이기를 원한다, 발이 미끄러지는 어색함이 없도록.
4. 플레이어로서, 점프·낙하·착지 동작과 착지 먼지·소리를 원한다, 옥상에서 뛰어내리는 순간이 실감 나도록.
5. 인간 플레이어로서, 버블건을 조준하며 옆이나 뒤로 이동할 때 문워크가 아닌 자연스러운 걸음을 원한다, 방어 중의 움직임이 어색하지 않도록.
6. 동물 플레이어로서, 곰은 묵직하게 토끼는 깡충깡충처럼 종마다 다른 움직임 성격을 원한다, 어떤 동물이 되었는지 몸으로 느끼도록.
7. 동물 플레이어로서, 공격 버튼을 누르면 짧은 예비동작 뒤 휘두르는 동작이 나오기를 원한다, 공격하는 손맛이 있도록.
8. 인간 플레이어로서, 동물의 예비동작을 보고 반응할 짧은 틈을 원한다, 버블건으로 막아 낼 기회가 있도록.
9. 동물 플레이어로서, 공격이 빗나가면 헛스윙 동작과 소리를 원한다, 실패도 분명히 알 수 있도록.
10. 동물 플레이어로서, 공격이 명중하면 명중음·효과와 함께 짧게 멈추는 손맛을 원한다, 잡았다는 쾌감이 있도록.
11. 인간 플레이어로서, 버블에 맞은 동물이 비틀거리며 밀려나는 모습을 원한다, 방어가 통했다는 것을 바로 알도록.
12. 동물 플레이어로서, 버블에 맞아 밀릴 때 땅과 공중에서 다르게 미끄러지기를 원한다, 밀림이 물리적으로 그럴듯하도록.
13. 플레이어로서, 변신 순간 짧은 연출과 소리를 원한다, 전세가 뒤집히는 순간을 놓치지 않도록.
14. 변신한 플레이어로서, 변신 연출 중에도 기존 규칙대로 움직일 수 있기를 원한다, 연출 때문에 불리해지지 않도록.
15. 플레이어로서, 카메라가 부드럽게 따라오고 내가 맞거나 때리거나 착지할 때만 살짝 흔들리기를 원한다, 다른 사람의 공방 때문에 내 화면이 흔들리지 않도록.
16. 멀미를 느끼는 참가자로서, 화면 흔들림을 끌 수 있기를 원한다, 편하게 플레이하도록.
17. 인간 플레이어로서, 동물의 발소리와 울음이 방향과 거리를 가진 3D 소리로 들리기를 원한다, 보이지 않는 곳의 위협을 귀로 알아채도록.
18. 플레이어로서, 마을의 환경음과 준비·추격·마지막 30초에 따라 바뀌는 배경음악을 원한다, 라운드의 긴장 변화를 느끼도록.
19. 인간 플레이어로서, 재장전·빈 탄창 소리를 원한다, 화면을 보지 않아도 무기 상태를 알도록.
20. 플레이어로서, 원격 참가자가 들쭉날쭉하지 않고 실제 공격·점프 동작을 보이며 움직이기를 원한다, 사람과 함께 노는 느낌이 들도록.
21. 플레이어로서, 봇이 지그재그 없이 부드럽게 움직이고 사람처럼 약간 늦게 반응하기를 원한다, 봇이 기계처럼 보이지 않도록.
22. 플레이어로서, 상자·통·항아리를 몸이나 버블로 밀 수 있기를 원한다, 마을이 살아 있는 장소처럼 느껴지도록.
23. 플레이어로서, 밀린 소품이 모든 참가자에게 같은 위치로 보이고 길을 막지 않기를 원한다, 소품 때문에 공방 규칙이 바뀌지 않도록.
24. 플레이어로서, 나무와 깃발이 바람에 흔들리고 랜턴이 빛나며 색감이 정돈된 화면을 원한다, 마을의 분위기를 느끼도록.
25. 사양이 낮은 PC의 참가자로서, 그래픽 품질을 낮음/보통/높음으로 고르고 저장할 수 있기를 원한다, 프레임이 떨어지지 않도록.
26. 호스트로서, 관성·공격 예비동작·히트스톱·피격 경직·봇 반응 지연을 실시간 슬라이더로 조절하고 0으로 끌 수 있기를 원한다, 실감과 반응성의 균형을 실플레이로 비교하도록.
27. 호스트로서, 모든 실감 슬라이더를 0으로 두면 기존 프로토타입과 같은 판정·이동을 얻기를 원한다, 개선 전후를 공정하게 비교하도록.
28. 일반 참가자로서, 호스트 전용 실감 설정은 바꿀 수 없지만 내 PC의 그래픽 품질과 흔들림은 바꿀 수 있기를 원한다, 공정성과 개인 편의를 함께 얻도록.
29. 제작자로서, 사용한 CC0 소리의 출처와 라이선스 기록을 원한다, 상용 출시 때 문제가 없도록.
30. 제작자로서, 개선 전후 같은 장면 비교 영상을 받고 직접 플레이해 판정하기를 원한다, 무엇이 실감 나게 바뀌었는지 확인하도록.

## Implementation Decisions

### 상태와 설계 확인

제품 규칙은 2026-10-06 실감 개선 Grill 합의(CONTEXT.md 「실감 개선 정렬」)를 따른다. 아래 모듈 구성과 테스트 경계는 PRD 작성 중 각각 별도로 제안하고 사용자 확인을 받았다. 기존 core-playtest PRD의 PlaytestSession·MatchWorld·BotDirector·PlaytestSettings·GamePresentation 구성은 유지하며, 이 PRD는 그 안에 새 모듈을 만들거나 기존 모듈을 넓힌다. 기준 코드는 최신 `feature/animal-balance` 계열 preview이며 Built-in 렌더 파이프라인을 유지한다.

### 주요 모듈 — 설계 축

| 모듈 | 작은 공개 인터페이스 | 내부에 숨기는 구현 | 경계와 이유 |
|---|---|---|---|
| CharacterMotion (신규, 판정) | 한 캐릭터의 다음 운동 상태 계산 하나: 현재 운동 상태·입력·적용 설정·시간 → 다음 운동 상태 | 가속·감속, 공중 조작 감소, 피격 경직, 히트스톱 정지, 넉백의 지면·공중 마찰, 종별 움직임 성격 | Unity 물리 없이 결정적으로 계산하며 "실감 값 0이면 기존 이동과 동일"을 한곳에서 보장한다. 호스트만 실행한다. |

| AudioDirector (신규, 표현) | 사건 하나, 현재 라운드 단계 | 3D 공간음, 종별 발소리·울음, 환경음, 준비·추격·마지막 30초 BGM, 재장전·빈 탄창·변신·UI 소리, 동시 재생 제한, CC0 소리 목록과 합성음 대체 | 소리 출처·라이선스·누락 대체를 한곳에 모은다. |

| PlaytestSettings (확장) | 기존 인터페이스 유지 | 신규 실시간 값: 관성 시간, 공격 예비동작, 히트스톱, 피격 경직, 봇 조준 반응 지연·오차 | 기존 범위 검증·저장·구 설정 호환·호스트 전용 권한을 재사용한다. |
| PlaytestSession 네트워크 (확장) | 기존 인터페이스 유지 | 운동·동작 상태와 소품 위치 스냅샷, 스냅샷 버퍼 보간, private protocol 버전 갱신 | 원격 화면이 호스트 판정 상태를 보간해 같은 동작을 보여 준다. |
| BotDirector (확장) | 기존 인터페이스 유지 | 경로 다듬기, 감속 입력, 조준 반응 지연·오차 | 봇은 계속 사람과 같은 입력·판정 경로로만 움직인다. |

인터페이스 후보는 확정된 코드 API가 아니다. 표현 모듈(CharacterAnimator·FeelDirector·AudioDirector·TownAtmosphere)은 승패·진영·위치를 바꾸지 않고 공개 상태·사건만 읽는다.

### 규칙 영향 원칙

- 관성 시간, 공격 예비동작, 히트스톱, 피격 경직, 봇 조준 반응 지연·오차는 승패에 영향을 주는 값이다. 기본값은 작게 두고 호스트의 실시간 디버그 패널에서 조절·0으로 끌 수 있다.
- 모든 값이 0이면 즉시 최고속·즉시 정지 이동, 클릭 프레임 근접 판정, 정지 없음, 경직 없음, 현재 봇 조준과 같아야 한다.
- 변신 연출(0.3~0.5초)은 겉모습만 바꾼다. 맞은 순간 판정상 즉시 동물이며 연출 중에도 이동할 수 있고 공격은 기존 중간 변신 유예 설정을 따른다.
- 히트스톱은 매치 전체가 아니라 관련 캐릭터만 짧게 멈춘다. 카메라 흔들림은 때린 사람·맞은 사람·근처 착지자의 로컬 카메라에만 적용하며 겹쳐도 최대치를 넘지 않는다.

### 움직임과 애니메이션

- 보유 Polyperfect 클립을 우선 사용한다. 인간은 Humanoid로 걷기·달리기·옆/뒷걸음 표현과 발 IK 적용이 가능하며, 동물 6종은 보유 Walk·Run·Attack·Jump 계열 클립을 종별로 연결한다. 공격 클립이 없는 펭귄은 코드 기반 달려들기와 Shake 클립으로 대체한다.
- 동물 종별 속도·점프·밀림 배율은 기존 합의값을 유지하고, 종별 움직임 성격은 가속·감속 곡선과 동작 표현으로 만든다. 배율 자체를 바꾸지 않는다.
- 관성 도입으로 정확한 속도×시간 이동을 검사하던 기존 테스트는 실감 값 0 조건과 새 관성 조건으로 나눠 갱신한다.

### 소품과 환경

- 밀리는 소품은 상자·통·항아리 같은 가벼운 것만 대상으로 한다. 인간·동물·버블에 밀리며 호스트가 판정하고 모든 참가자에게 같은 위치로 동기화한다. 캐릭터가 밀고 지나갈 수 있을 만큼 가벼워 길을 막지 않는다. 쉘터 안·입구 근처에는 배치하지 않고 라운드 시작 시 원래 자리로 되돌린다. 동기화 대상은 움직이는 소품으로 제한한다.
- 중간 참가·재접속자는 현재 소품 위치를 받는다. 라운드 종료 시 진행 중 연출·히트스톱을 끊는다.

### 소리

- 보유 Polyperfect 소리와 기존 합성음에 CC0 무료 효과음·음악만 추가한다. 출처·라이선스 기록을 저장소에 남기며 CC0가 아닌 소리는 사용자 확인 없이 쓰지 않는다.
- 소리 파일이 없거나 확보하지 못한 항목은 합성음으로 대체하고 플레이를 막지 않으며, 해당 범위를 미완료로 보고한다.
- 12명 동시 사건은 기존 재생 간격 제한을 확장하고 동시 재생 수를 제한한다.

### 네트워크

- 새 동기화 필드 때문에 private protocol 버전을 올리며 구 빌드는 연결 전에 거부한다(기존 방식).

### 진행 순서

Slice는 ① 몸의 무게감 → ② 타격감 → ③ 소리 → ⑤ 원격·봇 → ④ 화면·환경 순서로 진행한다. ②는 ①의 이동 애니메이션 위에, ⑤의 동작 동기화는 ①②의 새 동작 위에 얹는다.

## Testing Decisions

### 공개 경계 — 테스트 축

이 테스트 경계는 모듈 설계와 별도로 제안하고 사용자 확인을 받았다. 새 경계를 만들지 않고 core-playtest에서 쓰는 기존 경계 세 곳을 재사용한다. CharacterMotion·CharacterAnimator·FeelDirector·AudioDirector의 private 계산이나 내부 컬렉션에 직접 결합한 테스트를 만들지 않는다.

- **공개 세션 경계(Edit Mode·Unity 없는 core 실행):** 공개 명령과 공개 상태·사건만으로 다음을 검증한다. 실감 값 0일 때 기존 이동·판정과 동일, 예비동작 후 명중 시점과 헛스윙 사건, 피격 경직, 히트스톱의 관련 캐릭터 한정, 소품의 라운드 시작 복귀, 봇 반응 설정 적용, 신규 설정 범위 검증과 구 설정 호환, 호스트 전용 권한.
- **Unity Play Mode(같은 진입점):** 실제 CharacterController·물리·Animator·카메라·AudioSource로 관성 이동, 실제 Animator 상태 전환(걷기·달리기·점프·착지·공격·피격), 관련 참가자 카메라만 흔들림, 3D 공간음 재생과 동시 재생 제한, 소품이 밀리되 캐릭터 통행을 막지 않음, 품질 단계 적용을 확인한다.
- **실제 소켓 네트워크 경계:** 원격 클라이언트가 보는 동작 단계·소품 위치가 호스트와 일치하고 중간 참가자가 현재 소품 위치를 받으며 구 프로토콜 빌드가 연결 전에 거부되는지 확인한다.

### Prior art와 대체 허용 범위

- 기존 AnimalBalance·SettingsMovement·CombatWorld·Effects·Bot·Network 테스트가 같은 경계를 사용한다. 정확한 속도×시간 검사는 실감 값 0 조건으로 유지하고 관성 조건 검사를 추가한다.
- 비교 영상과 사용자 직접 플레이 판정은 테스트가 아니라 제품 완료 증거다. 자동 검사 green이나 엔진 자동 입력 영상으로 사람의 실감 판정을 대신하지 않는다.
- 소리 확보 실패·저장 실패는 격리된 어댑터로 representative 재현한다. 실제 렌더·소리·네트워크·플레이 감상은 live 근거가 필요하다.

## Product Definition of Done

- **Target environment:** macOS arm64 독립 실행 Development 빌드(Builds/Playtest-<커밋>/의 ZIP)와 Unity 개발 환경. 원격·소품 동기화는 실제 로컬 소켓 다중 프로세스로 검증한다. Windows 실기·2~4인 다기기 재미 검증은 core-playtest의 남은 항목이며 이 PRD 완료 조건에 포함하지 않는다.
- **Core value delivered:** 사용자가 Mac 빌드를 직접 플레이했을 때 움직임·타격·소리·다른 캐릭터·마을 환경이 기존 빌드보다 실감 나게 느껴진다. 각 Slice는 사용자의 직접 플레이 판정을 받아야 완료다.
- **Rule safety:** 모든 실감 값 0이면 기존 판정·이동과 같고, 표현 모듈이 승패·진영·위치를 바꾸지 않는다.
- **Persistence/read-back:** 그래픽 품질·흔들림은 재실행 후 시작 화면과 Esc 메뉴에서 다시 확인한다. 호스트가 저장한 실감 슬라이더 값은 재실행 후 디버그 패널에서 다시 확인한다.
- **Failure/degraded behavior:** 소리 파일 누락은 합성음 대체, 품질 저장 실패는 이번 실행 적용 안내, 구 빌드는 연결 전 거부, 저사양은 품질 단계로 대응한다.
- **Evidence:** Slice마다 기존·개선 빌드의 같은 장면 비교 영상(장면당 5~8초), 빌드 영수증(커밋·테스트 결과·ZIP 해시), CC0 출처 기록, 사용자 플레이 판정 기록. live/representative를 구분한다.
- **Completion rule:** 모든 critical PA가 통과하고 사용자가 각 Slice를 "더 실감 난다"고 판정해야 완료로 선언한다. 실패·미실행은 그대로 남긴다.
- **Allowed verification effects:** 로컬 빌드·실행·설정 저장, 격리 프로필, 로컬 다중 프로세스 소켓 세션, CC0 소리의 다운로드와 저장소 기록.
- **Authorization blockers:** 유료 에셋·소리 구매, CC0가 아닌 라이선스 사용, 구매 에셋 원본 공개, main 병합, 공개 배포는 별도 사용자 승인 대상이다.

## Product Acceptance Scenarios

### PA-1 — 무게감 있는 이동과 동작 (critical)

- **Environment:** macOS 빌드, live.
- **Initial state:** 기본 실감 값, 인간과 동물(6종 각각)을 조작할 수 있는 라운드.
- **Action:** 출발·정지·급회전, 버블건 조준 중 옆·뒷걸음, 옥상 점프·낙하·착지를 수행한다.
- **Observable result:** 짧은 가속·감속이 보이되 방향 전환이 답답하지 않다. 속도에 맞는 걷기·달리기로 발이 미끄러지지 않고, 점프·낙하·착지 동작과 착지 효과가 나온다. 옆·뒷걸음이 문워크로 보이지 않는다. 곰은 묵직하고 토끼는 튀는 등 종별 성격이 구분된다.
- **Persistence/read-back:** 해당 없음.
- **Failure/degraded:** 발 미끄러짐·동작 깜빡임·지형 끼임은 결함이다.
- **Evidence:** 기존·개선 빌드 비교 영상, Play Mode 이동·Animator 검사 결과.
- **Cleanup:** 실행 종료.

### PA-2 — 공격 예비동작·피격 반응·변신 연출 (critical)

- **Environment:** macOS 빌드, live.
- **Initial state:** 기본 실감 값, 동물과 인간이 가까운 라운드.
- **Action:** 동물로 명중·헛스윙 공격을 하고, 인간으로 버블을 맞혀 동물을 밀어낸다.
- **Observable result:** 공격은 짧은 예비동작 후 스윙하며 명중 시 명중음·효과·짧은 정지, 빗나가면 헛스윙 동작·소리가 나온다. 버블 맞은 동물은 비틀거리며 밀리고 땅·공중 마찰이 다르다. 변신은 0.3~0.5초 연출로 보이며 연출 중에도 이동할 수 있고 공격은 중간 변신 유예를 따른다.
- **Persistence/read-back:** 공개 사건 기록에서 예비동작·명중·변신 시각을 확인한다.
- **Failure/degraded:** 연출 때문에 판정이 지연·중복되거나 변신 연출이 두 번 재생되면 결함이다.
- **Evidence:** 비교 영상, 공개 세션 경계 검사 결과.
- **Cleanup:** 실행 종료.

### PA-3 — 카메라 흔들림·히트스톱의 관련자 한정과 끄기 (critical)

- **Environment:** 로컬 소켓 다중 프로세스(호스트+클라이언트) 및 macOS 빌드, live.
- **Initial state:** 두 참가자가 서로 떨어진 위치에 있는 라운드.
- **Action:** 한쪽에서 공격·피격·착지를 발생시키고, 다른 쪽은 관찰한다. 이후 화면 흔들림을 끄고 반복한다.
- **Observable result:** 관련된 참가자의 카메라만 흔들리고, 히트스톱은 관련 캐릭터만 멈추며 다른 참가자의 플레이는 멈추지 않는다. 흔들림을 끄면 흔들리지 않는다. 여러 사건이 겹쳐도 흔들림이 최대치를 넘지 않는다.
- **Persistence/read-back:** 흔들림 끄기가 재실행 후 유지된다.
- **Failure/degraded:** 무관한 참가자 화면 흔들림·매치 전체 정지는 결함이다.
- **Evidence:** 양쪽 화면 영상, Play Mode 카메라 검사 결과.
- **Cleanup:** 프로세스 종료, 격리 프로필 정리.

### PA-4 — 3D 공간음과 단계별 소리 (critical)

- **Environment:** macOS 빌드, live(소리 포함 영상).
- **Initial state:** 기본 설정 라운드.
- **Action:** 보이지 않는 위치에서 동물이 접근하게 하고, 준비→추격→마지막 30초를 진행하며 재장전·빈 탄창·변신을 발생시킨다.
- **Observable result:** 동물 발소리·울음이 방향·거리에 따라 들린다. 환경음과 단계별 배경음악이 바뀐다. 재장전·빈 탄창·변신·공격 소리가 나온다. 12명 동시 사건에서도 소리가 깨지지 않는다.
- **Persistence/read-back:** 해당 없음.
- **Failure/degraded:** 소리 파일이 없으면 합성음으로 대체하고 플레이를 막지 않는다. 대체된 항목은 미완료로 보고한다.
- **Evidence:** 소리가 포함된 비교 영상, Play Mode 3D 재생·동시 재생 제한 검사 결과.
- **Cleanup:** 실행 종료.

### PA-5 — CC0 소리 출처와 라이선스 기록 (critical)

- **Environment:** 저장소와 빌드 산출물.
- **Initial state:** 새로 추가한 소리 파일들.
- **Action:** 추가된 모든 소리를 출처 기록과 대조한다.
- **Observable result:** 모든 신규 소리가 보유 에셋·합성음·CC0 중 하나로 기록되어 있고 출처를 다시 확인할 수 있다. CC0가 아닌 소리는 없다.
- **Persistence/read-back:** 기록 파일을 다시 읽어 소리 목록과 일치함을 확인한다.
- **Failure/degraded:** 출처 미기록·비CC0 소리는 결함이며 사용자 확인 전까지 포함하지 않는다.
- **Evidence:** 출처 기록과 소리 목록 대조 결과.
- **Cleanup:** 해당 없음.

### PA-6 — 원격 캐릭터의 자연스러운 움직임과 동작 (critical)

- **Environment:** 로컬 소켓 다중 프로세스, live.
- **Initial state:** 호스트와 클라이언트가 같은 라운드에 참가.
- **Action:** 호스트 쪽 캐릭터가 이동·점프·공격·피격·조준 상하 이동을 한다. 구 프로토콜 빌드로도 접속을 시도한다.
- **Observable result:** 클라이언트 화면에서 원격 캐릭터가 들쭉날쭉하지 않게 움직이고 공격·점프·피격 동작과 조준 상하각이 호스트와 같게 보인다. 대기·달리기가 깜빡이지 않는다. 구 빌드는 연결 전에 거부된다.
- **Persistence/read-back:** 해당 없음.
- **Failure/degraded:** 패킷 지연에도 순간이동이 반복되지 않는다. 큰 차이는 기존처럼 위치를 맞춘다.
- **Evidence:** 호스트·클라이언트 나란히 비교 영상, 네트워크 경계 검사 결과.
- **Cleanup:** 프로세스 종료.

### PA-7 — 사람처럼 움직이는 봇 (critical)

- **Environment:** macOS 빌드, live.
- **Initial state:** 혼자 시작해 11봇과 플레이.
- **Action:** 봇의 이동·추격·방어·조준을 관찰하고 봇 반응 지연·오차 슬라이더를 0과 기본값으로 비교한다.
- **Observable result:** 기본값에서 봇이 45° 지그재그 없이 부드럽게 이동하고 감속하며, 조준에 약간의 반응 지연·오차가 있다. 0이면 현재 봇과 같은 조준이다. 쉘터 공방과 우회 행동은 유지된다.
- **Persistence/read-back:** 해당 없음.
- **Failure/degraded:** 봇 정체·왕복·고립이 새로 생기면 결함이다.
- **Evidence:** 비교 영상, Bot Play Mode 검사 결과.
- **Cleanup:** 실행 종료.

### PA-8 — 밀리는 소품의 동기화·통행·복귀 (critical)

- **Environment:** 로컬 소켓 다중 프로세스와 macOS 빌드, live.
- **Initial state:** 소품이 배치된 마을, 호스트와 클라이언트 참가.
- **Action:** 몸과 버블로 소품을 밀고, 골목이나 쉘터 방향으로 밀어 넣어 본다. 중간 참가자를 들여보내고 라운드를 넘긴다.
- **Observable result:** 소품이 밀리고 모든 참가자에게 같은 위치로 보인다. 캐릭터는 소품을 밀고 지나갈 수 있어 길이 막히지 않는다. 쉘터 안·입구 근처에는 처음부터 소품이 없다. 중간 참가자는 현재 위치를 받고, 다음 라운드 시작 시 원래 자리로 돌아간다.
- **Persistence/read-back:** 라운드 시작 후 소품 위치를 초기 배치와 대조한다.
- **Failure/degraded:** 참가자 간 위치 불일치·통행 차단은 결함이다.
- **Evidence:** 양쪽 화면 영상, 공개 경계·네트워크 검사 결과.
- **Cleanup:** 프로세스 종료.

### PA-9 — 마을 분위기와 그래픽 품질·흔들림 설정 (critical)

- **Environment:** macOS 빌드, live.
- **Initial state:** 설정 파일이 없는 격리 프로필.
- **Action:** 시작 화면과 Esc 메뉴에서 품질을 낮음/보통/높음으로 바꾸고 흔들림을 끄고 재실행한다. 저장 실패를 격리 어댑터로 재현한다(representative).
- **Observable result:** 최초 실행은 높음·흔들림 켜기다. 높음에서 톤매핑·색보정·블룸·AO, 흔들리는 나무·깃발, 랜턴 빛이 보이고 낮음으로 갈수록 그림자·포스트프로세싱·흔들림이 줄어든다. 선택은 즉시 적용된다. 일반 참가자도 이 메뉴를 쓸 수 있다.
- **Persistence/read-back:** 재실행 후 선택값이 시작 화면과 Esc 메뉴에 유지된다.
- **Failure/degraded:** 저장 실패 시 "이번 실행에만 적용됩니다" 안내가 보이고 플레이는 계속된다.
- **Evidence:** 품질 단계별 화면, 재실행 확인 화면, 비교 영상.
- **Cleanup:** 격리 프로필 정리.

### PA-10 — 실감 값 0이면 기존 판정과 동일, 호스트 전용 조절 (critical)

- **Environment:** 공개 세션 경계와 macOS 빌드, live+representative.
- **Initial state:** 호스트와 일반 참가자가 있는 라운드.
- **Action:** 호스트가 관성·예비동작·히트스톱·피격 경직·봇 반응 값을 실시간으로 바꾸고 모두 0으로 둔 뒤 저장·재실행한다. 일반 참가자는 같은 값을 바꾸려 시도한다.
- **Observable result:** 값 변경이 실시간 반영되고, 모두 0이면 즉시 최고속·즉시 정지, 클릭 프레임 판정, 정지·경직 없음, 기존 봇 조준과 같다. 일반 참가자는 바꿀 수 없다. 범위 밖 값은 거부된다.
- **Persistence/read-back:** 재실행 후 디버그 패널에서 저장한 값을 다시 확인한다. 이전 설정 파일은 신규 값에 기본값을 사용한다.
- **Failure/degraded:** 범위 밖 값은 기존 검증 방식으로 거부한다.
- **Evidence:** 공개 경계 검사 결과, 0/기본값 비교 영상.
- **Cleanup:** 격리 프로필 정리.

### PA-11 — 사용자 직접 플레이 실감 판정 (critical)

- **Environment:** 사용자의 Mac, Slice마다 전달한 빌드 ZIP, live.
- **Initial state:** 기존 빌드와 해당 Slice 개선 빌드, 비교 영상.
- **Action:** 사용자가 두 빌드를 플레이하고 비교 영상을 본다.
- **Observable result:** 사용자가 해당 Slice 영역이 "더 실감 난다"고 판정한다. 부족하면 지적 사항이 기록되고 같은 Slice의 수정·재검증으로 돌아간다.
- **Persistence/read-back:** 판정과 지적 사항을 Slice 기록에 남긴다.
- **Failure/degraded:** 판정 전에는 Slice를 완료로 표시하지 않는다.
- **Evidence:** 사용자 판정 기록, 빌드 영수증, 비교 영상.
- **Cleanup:** 해당 없음.

## Out of Scope

- URP·HDRP 전환과 사실적 그래픽 리마스터. 로우폴리 아트 스타일 변경.
- 랙돌·전면 물리 시뮬레이션, 파괴 가능한 지형, 날씨·시간대 변화.
- 길을 막는 무거운 소품이나 소품을 이용한 봉쇄 전략.
- 변신 연출 중 행동 불능 같은 새 규칙, 장시간 포획.
- 캐릭터별 특수능력·상성·희귀도·뽑기·Balloon맨, 게임패드 지원.
- 유료 에셋·소리 구매와 CC0가 아닌 라이선스 사용.
- Windows 실기, 2~4인 다기기 재미 검증, 공식 integration·main 병합(core-playtest와 별도 승인 항목).
- 봇의 새 전술·목표 선택 같은 AI 판단 개선(이번에는 움직임·조준의 자연스러움만).
