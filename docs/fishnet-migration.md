# FishNet movement playtest — 2026-10-13

Live room networking uses FishNet/Tugboat UDP. The previous TCP PrivateRoomHost/Client are retained only as Core test utilities; NetworkPresentation never instantiates them.

FishNet source is embedded in game/Packages/com.firstgeargames.fishnet at upstream tag 4.7.3, commit 73f30cf2425dc808a4f463f0a233d386010810b3. The upstream package.json still reports 4.7.2. Runtime is unmodified. r6 patches PredictionProcessor.InitializeCollections to create 300-entry prediction/reconcile histories rather than the generic 60-entry default (five seconds at this game's 60 Hz rate). Licenses and third-party notices accompany the package.

- Server world and owner movement run at 60 ticks/sec using TimeManager.TickDelta.
- r5 sets the bounded server replicate queue to 120 inputs (two seconds at 60 Hz), retaining excessive-input protection. The upstream default of 15 inputs discarded real movement when Wi-Fi delivered a half-second burst. Both host and guest must run r5 for this correction.
- r6 sends input over the reliable ordered channel to retain all ticks during short Wi-Fi packet-loss runs; reconcile remains unreliable. The external CharacterController simulates only created input on the server and pins the owner's acknowledgement to the actual processed tick. Client histories retain five seconds, so delayed acknowledgement does not erase still-pending movement. Both PCs must use r6 for this fix; beyond the bounded server queue, severe outages still require position correction.
- Host and connected humans receive FishPredictedMotor; bots continue using the existing server AI and movement rules.
- Replicate contains input only, with jump/reload/attack held between render updates and tick consumption. Client positions and tuning are never accepted as input.
- Reconcile restores position, rotation, planar momentum, vertical velocity, knockback, grounded state, buffered jump, round, and server movement tuning/restraints. FishNet then replays pending input history.
- CharacterController is disabled/re-enabled around position restoration. Grounding is explicit CollisionFlags from one movement call, rather than a second correction Move invalidating grounding.
- Owner physics bypass snapshot interpolation. FishNet UniversalTickSmoother interpolates a separate graphical parent (including the gun) between simulation ticks, corrects queued ticks during replay, and drives the camera anchor. Animation advances each render frame from reconciled movement/action state, without writing the smoothing parent. Spectators use existing snapshot interpolation. Full prediction of combat effects and moving-platform rollback are outside this first movement migration.
- r5 uses fixed two-tick interpolation for the predicted owner, with adaptive RTT interpolation disabled. The owner's presentation follows current prediction rather than a half-second of historical movement. High-RTT and a real duplex UDP relay releasing packets every 0.5 seconds have regression coverage for visible trailing and post-release backward correction.
- Room snapshots are Deflate-compressed before reliable UDP transmission, with bounded decompression and explicit version rejection for earlier protocols. Remote player collision controllers remain enabled for predicted movement. Reliable room broadcasts preserve host match rules, settings, bot handoff, reconnect identity and effects. r6 prediction inputs use reliable ordered delivery; reconcile state remains unreliable.
- Room protocol is avh-fishnet-3. Previous TCP builds and room codes cannot join this build. Both PCs must use this release and create a new room.
- LAN/VPN endpoint codes are preserved; no public relay/NAT traversal service is added. Allow the application through the local UDP firewall.

Validation: FishNetPredictionTests exercises two real UDP endpoints, 120ms injected latency, 10% unreliable packet loss and 5% out-of-order delivery. It checks one-frame jump receipt, actual input replay, convergence after stopping, and correction of injected position divergence. Native two-process probes and platform build receipts are stored alongside delivered ZIPs. Physical two-PC Wi-Fi and Windows runtime validation remain user playtests.

Revision 2 also records compressed/raw snapshot bytes and maximum final reconciliation displacement in the copyable connection diagnostics. Frame probes record both physical and graphical positions, and can opt into high frame rates. Local native results do not establish performance on the user’s two-PC Wi-Fi.

Revision 3 (2026-10-14): the graphical tracker follows the controller origin (local position zero, rotation identity, scale one), rather than the graphical child’s transient pose at initialization. A correction before the first rendered frame can otherwise permanently bind a negative vertical offset. The regression test reproduces a two-metre underground display on r2 while physics remains grounded, then verifies initialization and subsequent vertical correction settle within 5cm after the fix. Connection diagnostics distinguish body Y from graphical Y.
