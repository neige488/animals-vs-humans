# S5 비공개 네트워크 구현

## 범위와 연결 방식

기존 OS 소켓의 TCP를 사용한다. `PrivateRoomCode`는 직접 도달할 수 있는 IPv4 주소·임시 포트·무작위 방 capability를 코드로 표현하며, `PrivateRoomHost`의 슬롯·권한 판정과 분리된다. 계정·비용·외부 서비스·Steam 연동을 추가하지 않는다. 동일 LAN 또는 이미 연결된 VPN을 사용하는 첫 테스트용이다. 일반 인터넷 NAT 관통, relay, public matchmaking을 제공한다고 주장하지 않는다. 호스트 주소는 네트워크 인터페이스에서 제안하며 시작 화면에서 고칠 수 있다.

비공개 코드는 참가 권한을 포함하므로 초대한 테스터에게만 공유한다. 호스트는 방 코드 복사 버튼을 제공한다. 코드를 로그나 검수 자료에 출력하지 않는다. 전송은 신뢰하는 LAN/VPN 전용 TCP이며 자체 TLS는 없다. 공개 인터넷의 적대적 환경에 대한 인증·암호화 완성으로 해석하지 않는다.

## 동작

- 호스트가 물리·공방·라운드 판정을 실행한다. 원격 메시지에는 입력만 있고 슬롯·위치·타격 결과·설정 변경 주장은 없다.
- 호스트의 준비 완료 처리에서 최신 인간 봇을 우선 배정한다. 결과 화면 중에는 봇을 유지하고 다음 준비 시점에 배정한다. 원래 슬롯이 같은 라운드의 봇이면 재접속에 우선 사용한다.
- 닉네임과 별개의 무작위 식별 비밀을 같은 클라이언트 인스턴스의 재시도 동안 유지한다. 닉네임을 복제해도 슬롯을 탈취할 수 없다. 앱 자체를 종료한 뒤에는 새 식별로 일반 참가한다.
- 이탈은 상태 변경 없이 봇 소유권으로 되돌리고, 인계 시 이전 입력을 초기화한다. 전투 상태는 슬롯 객체에 남아 탄창·재장전·유예도 함께 보존된다.
- 단일 호스트 pump에서 정원을 원자적으로 결정한다. 중복 identity는 활성 연결을 밀어내지 않는다. 취소는 해당 socket을 폐기하므로 늦은 비동기 연결 완료를 적용하지 않는다.
- 호스트 종료·10초 무응답은 승패 없이 중단 안내와 시작 화면 복귀로 연결된다. 연결 시도는 8초에 시간 초과한다. 무인증/로딩 peer도 10초 미응답이면 정리한다.
- 길이 64 KiB 상한의 typed frame만 수신한다. 원격 타입 이름·실행 객체·BinaryFormatter를 받지 않는다. 명시적인 프로토콜 버전이 다른 빌드는 참가를 거부한다. 스키마 fingerprint 회귀 테스트가 필드 변경 시 버전 검토를 요구한다.
- 20 Hz로 호스트 상태·설정 버전·예약값·캐릭터 방향·버블·터짐 효과를 전달한다. 클라이언트는 판정 없이 캐릭터를 보간하고 버블을 표시한다. 호스트만 설정 UI에 접근한다.

## 검증

- `bash scripts/test-core.sh`: 실제 loopback socket을 사용한 참가·인계·이탈·재접속·닉네임 복제·동일 identity·12명 정원 경합·취소·결과 대기·잘못된 길이·현재/예약 설정·잘못된 입력 검증. Unity 물리 검증과 구분한다.
- `NetworkPlayTests.RealSocketInputMovesAuthoritativeBodyAndRemoteMirror`: Unity 실제 CharacterController에 TCP 입력을 전달하고 원격 위치·이탈 봇 복원을 확인한다. 한 프로세스의 대표 자동 클라이언트이며 사람이 참여한 양 OS 검증이 아니다.
- TCP binding은 기본 sandbox에서 차단되어 승인된 로컬 테스트 권한으로 실행했다.

## 현재 제한

프레임·수신 버퍼 상한 확대는 자동 승인 검토에서 자원 고갈 방어 약화로 거절되어 실행하지 않았다. 대안으로 64 KiB 프레임, 기존 수신 버퍼와 배열 512 상한을 유지한 채 버블을 128개 조각으로 전송한다. 한 pump에서 최대 8조각을 보내며 무제한 송신 큐를 만들지 않는다. snapshot ID·offset·전체 개수를 검사하고 조각 수신이 2초간 정지하면 조립을 폐기하고 지연 안내를 표시한다. 진행 중인 큰 snapshot은 전체 전송이 2초를 넘더라도 완성 후 원자적으로 표시한다. 전체 표현 16,384개 상한을 넘으면 이유를 안내하고 재시도를 제공한다. 기본 공방은 20 Hz이며 극단적으로 많은 버블에서는 전체 표현 갱신 간격이 늘어난다. 실제 12명·극단 설정의 프레임률과 입력 지연은 아직 검증하지 않았다.

2026-09-29: standalone core 24/24 PASS, Unity 6000.6.3f1 실제 TCP PlayMode 1/1 PASS. S2/S4 후속 안정 커밋 c688f95를 통합했다. 최종 TCP PlayMode에서도 원격 발사·버블·탄창·설정 버전·이탈을 1/1 PASS로 확인했다. 결과 정원 오류 후속 변경은 핵심 소켓 테스트로 검증했다.


## Discovery 리뷰 후속 검증

- NET01: 현재 데스크톱 백엔드는 Mono다. `link.xml`로 reflection 직렬화가 읽는 AvH.Core 필드를 보존하고, 명시적 `avh-private-3` 프로토콜과 DTO 스키마 회귀 검사를 추가했다. IL2CPP 실제 빌드는 검증하지 않았다. 통합 브랜치의 `ResultSeconds` 필드는 이 브랜치에 없으므로 통합할 때 프로토콜 버전과 기대 스키마를 함께 갱신해야 한다.
- NET02/03: 각 host pump에서 상태와 표현을 한 번만 캡처해 공유한다. 완성된 새 snapshot에만 표현을 적용하고 ID HashSet으로 사라진 효과를 선형 처리한다. 1,000개 효과에서 500개로 줄이는 실제 Unity 표현 회귀가 포함된다.
- NET04/05: 소유권 claim/release/재접속 정책은 PlaytestSession이 캡슐화한다. 혼합 동물·인간 풀에서도 인간 우선을 검증하며 우선순위 반전 mutation이 해당 테스트를 실패시키는 것을 확인했다.
- NET06: 송신은 BeginSend/EndSend를 기다리지 않고 pump마다 진행한다. peer별 송신 큐 상한 131,080바이트를 유지하며 압력이 있으면 다음 표현 조각을 보류한다. 느린 reader 때문에 게임 스레드가 SendTimeout까지 대기하거나 즉시 강제 이탈시키지 않는다. 거절 응답은 최대 1초간 drain 후 닫는다. 초기 nonblocking Send 시도는 Mono에서 멈춰 폐기했으며 최종 실제 async 코드로 재검증했다.
- NET07: 전체 2초 제한을 수신 진행 기준 2초 정지 제한으로 바꿨다. 실제 소켓으로 12,000개 효과를 2초 넘게 순차 수신해 완성하는 테스트를 추가했다. 기존 프레임·수신·효과 개수 상한은 그대로다.
- NET08/09/10: 빈 닉네임·주소·빈 방 코드·잘못된 코드의 개별 안내, 호스트 종료 전용 문구와 복귀 동작을 추가했다. 방 capability와 재접속 identity는 16바이트 CSPRNG로 생성한다.
- NET11: Jump/Reload의 매 Step 소비는 기존 공통 구현을 유지한다. Attack 연속 입력은 새 입력 또는 연결 무응답 정리 시 해제된다. 별도 입력 만료가 없어 일시 전송 정지 동안 마지막 hold가 남을 수 있으며 실제 지연 플레이에서 추가 확인한다.
- NET12–17: 미인증 연결 32개·10초 정리와 이전 슬롯 이력 1,024개 상한을 유지한다. 실제 timeout 테스트는 약 10초가 필요하다. 버블 보간 개선과 실사용 가독성은 다인 플레이 검증으로 남긴다. 활성 설정 표시 통합은 root가 담당한다. 새 meta는 Unity가 생성했다. 비공개 코드는 노출 최소화를 위해 복사 버튼만 제공한다.

최종 standalone core 회귀: 31/31 PASS. 이는 실제 TCP loopback을 포함하며 Unity 물리와 실제 양 OS 플레이는 구분한다. 최종 Unity 결과는 별도 XML을 인계한다.
