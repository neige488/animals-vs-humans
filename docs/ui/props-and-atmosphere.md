# 밀리는 소품과 마을 분위기·품질 단계 (game-feel S5)

## 밀리는 소품

### 대상과 배치

- 마을 생성기(`ConfigureOwnedAssets.Village`)가 상자(`SM_Prop_Crate_01`)·통(`SM_Prop_Barrel_01`)·항아리(`SM_Prop_Pot_01`)를 충돌체 없이 `Pushable props` 아래에 고정 순서로 둔다. 현재 마을에서 상자 13·통 14·항아리 16, 모두 43개다.
- 쉘터 근처(`TownLayout.NearShelter`)의 것은 기존 고정 소품(볼록 충돌체)으로 남긴다. 기준은 세 쉘터 중심에서 수평 8m 안, 지붕 계단 아래(`RoofApproach`)에서 지붕까지 선분 양옆 4m 안이다. 작업장 작업대 위 항아리 2개, 작업장 뒤 상자 1개, 안뜰 뒤 상자·통 각 1개가 고정으로 남는다.
- 생성 프리팹은 Git 밖에 있다. 다른 작업 폴더의 예전 `Village.prefab`에는 컨테이너가 없으므로 `BuildPlaytest`가 빌드 전에 `ConfigureOwnedAssets.Configure`를 다시 실행한다. 보유 에셋이 없는 블록아웃 마을에는 밀리는 소품이 없다.

### 판정: 자체 결정적 계산 (Rigidbody 아님)

| 고려 | Rigidbody | 자체 계산(선택) |
|---|---|---|
| 같은 씬의 다른 세계(테스트, 원격 거울) | 전역 시뮬레이션이라 겹친 소품끼리 튕김 | 이 세계의 소품만 계산 |
| CharacterController | Rigidbody를 밀지 않아 접촉 처리를 따로 만들어야 함 | 같은 접촉 계산 한 곳 |
| 통행 보장 | 몸-소품 충돌을 꺼야 함 | 소품에 충돌체가 없어 몸·봇 A*·근접 시야선·카메라가 장애물로 보지 않음 |
| 동기화 | 위치+회전 전체 | 위치+yaw |

- 소품은 똑바로 선 원기둥 발자국(반지름 = 가로·세로 중 짧은 쪽의 절반, 높이 = 렌더 경계) 하나다. 넘어지거나 구르지 않는다.
- 몸(반지름 0.38m)이 닿으면 몸의 수평 속도 1.1배 + 겹친 깊이×6m/s로 앞서 밀린다. 몸은 절대 느려지지 않는다. 벽에 끼인 소품은 그 자리에 있고 몸이 지나간다.
- 버블은 스윕 경로에서 다른 단단한 것보다 소품을 먼저 만나면 소품에서 터지고 밀힘의 60%를 수평 속도로 준다(기본 8 → 4.8m/s).
- 소품끼리는 원 겹침으로 부딪혀 운동량을 나눈다. 정적 배경은 SphereCast로 막고 끼임은 ClosestPoint로 밀어낸다. 마찰 7m/s², 최고 9m/s, 바닥 레이캐스트로 경사를 타고 가장자리에서 떨어진다(맵 아래 20m에서 숨김, 다음 라운드 복귀).
- 라운드가 시작하면 모든 소품이 원래 자리·방향으로 돌아간다.
- 쉬던 소품이 1m/s 이상으로 밀리면, 버블은 항상, 공개 사건 `PropPushed`(Actor=민 슬롯, Target=소품 번호)를 남긴다. 소품당 0.25초에 한 번이다. 호스트·원격 모두 나무 두드림 합성음(`prop-knock`)과 작은 먼지를 보여 준다. 카메라 흔들림·히트스톱은 없다.

### 동기화

- 호스트 프레임(`NetworkMotionFrame.Props`, 소품 하나 10바이트: 번호·cm·0.01°)에는 지금 움직이거나 0.5초 안에 멈춘 소품만 싣는다. 아무것도 안 움직이면 빈 목록 4바이트다.
- 제자리를 벗어나 쉬는 소품은 0.5초마다 한 번 같이 실린다. 중간 참가·재접속자는 0.5초 안에 현재 위치를 받는다.
- 원격 화면은 몸과 같은 재생 버퍼(0.1초 뒤)로 두 프레임 사이를 보간한다. 프레임에 없는 소품은 마지막으로 보인 자리에 둔다. 6m 넘게 차이 나면 그 자리로 맞춘다. 라운드가 바뀌면 모두 제자리에서 시작한다.
- 스키마 변경으로 `avh-private-10`이다. 9 이하는 연결 전에 거부된다.

## 마을 분위기 (`TownAtmosphere`·`TownDressing`)

### 포스트프로세싱 호환성 결론

- `com.unity.postprocessing` 3.5.4(Post Processing Stack v2, 2026-03 릴리스)가 Unity 6000.6.3f1 Built-in 파이프라인에서 경고 없이 컴파일된다. 실제 카메라를 RenderTexture로 렌더해 낮음(후처리 없음)과 높음의 픽셀이 달라짐을 PlayMode 검사로 확인했다. macOS arm64 Development 빌드에서도 같은 화면을 확인했다.
- 대안으로 검토한 `OnRenderImage` 자체 셰이더(톤매핑·색보정·블룸·간단 AO)는 필요 없어 만들지 않았다.
- 런타임에 만든 카메라에 `PostProcessLayer`를 붙이고 `Resources/TownPostProcess`(패키지 `PostProcessResources` 참조)로 초기화한다. 이 참조가 있어 독립 빌드에도 셰이더가 들어간다. 효과는 숨김 전역 볼륨 하나에 둔다.

### 품질 단계

| 항목 | 높음 | 보통 | 낮음 |
|---|---|---|---|
| 톤매핑·색보정 | Neutral, 노출 +0.15, 따뜻함 3, 채도 +20, 대비 +14 | 같음 | 끔 |
| 블룸 | 강도 0.4, 임계 1.15 | 빠른 모드 | 끔 |
| AO | MSVO(컴퓨트 없으면 SAO) 0.7 | 끔 | 끔 |
| 그림자 | 부드러움·고해상도·110m | 딱딱함·중간·70m | 끔 |
| 나무·덤불·깃발 흔들림 | 전부, 진폭 100% | 나무·깃발만, 55% | 정지 |
| 랜턴 점광원(그림자 없음) | 12 | 6 | 0 |
| 픽셀 광원 수 | 4 | 2 | 0 |

- ACES는 이 저폴리 팔레트의 하늘·차양을 하얗게 바래게 해 Neutral을 골랐다.
- Synty 바람 셰이더는 Standard 재질 전환으로 사라졌다. 그래서 Transform을 흔든다. 나무·덤불은 밑동, 깃발은 깃대, 장터 리본은 줄을 축으로 위치마다 다른 위상으로 흔든다. 줄기 충돌체는 따로 있어 움직이지 않는다.
- 선택은 즉시 적용되고 이 PC에 저장된다(기존 `LocalDisplaySettings`).

## 성능 (PlayMode 대표 측정, 이 Mac)

`TownPresentationTests.TwelveBotsWithPropsLightsAndPostProcessingFrameCostPerQuality`: 12봇이 움직이는 마을, 소품 43개, 1280×720 렌더. 렌더 값은 1픽셀 되읽기로 GPU 완료까지 포함한다. Windows 실기 프레임은 범위 밖이다.
